# بررسی تداخل قالب و نسخه ۳.۰.۲

## دامنه بررسی و محدودیت
متن عمومی صفحه «چرا دیفن باخیا یهو پژمرده میشود؟» در سایت maneliplants.ir/new دریافت شد. دریافت مستقیم سورس HTML با curl به خطای TLS خورد. به پیشخوان، دیتابیس، کد ذخیره‌شده مقاله و نسخه نصب‌شده دسترسی نداشتم. بنابراین علت دقیق ظاهری این صفحه، سلکتور مقصر و نتیجه روی سایت واقعی تأیید نشده است. بررسی کد روی نسخه محلی ۳.۰.۱ انجام شده، نه فایل نصب‌شده روی سایت.

## یافته‌های قطعی در کد افزونه
- قرار گرفتن style داخل div، CSS را محلی نمی‌کند. body، header، footer، .container، .row، .summary و حتی * می‌توانند بیرون قطعه‌کد را تغییر دهند. JS هم به document اصلی دسترسی دارد.
- HTML خام بدون مرزبندی سند چاپ می‌شد؛ سند کامل دارای html/head/body، تگ بسته اضافی، یا ساختار ناقص می‌تواند DOM صفحه میزبان را تغییر دهد. سالم بودن HTML این مقاله هنوز بررسی نشده است.
- replace=true از عبارت منظم حریص برای استخراج div استفاده می‌کرد؛ این روش مرز واقعی قطعه‌کد را تشخیص نمی‌دهد.
- جایگزینی محتوای محصول می‌توانست مخفی‌سازی اجزای خرید و حذف هوک‌های ووکامرس را خودکار فعال کند.
- اجرای شورت‌کد و تعیین include برای همان صفحه ممکن بود خروجی را دوبار نمایش دهد.

## اصلاحات ۳.۰.۲
۱. حذف مخفی‌سازی ضمنی ووکامرس؛ جایگزینی محتوا به‌تنهایی دیگر اجازه حذف اجزای محصول نیست. رفتار قدیمی فقط با opt-in برنامه‌نویس از طریق فیلتر chs_allow_product_takeover با مقدار true فعال می‌شود. در حالت عادی این فیلتر را فعال نکنید.
۲. محدود کردن تزریق خودکار به نوشته اصلی کوئری تکی؛ عدم اجرا در مدیریت، feed و REST، یا نوشته دیگر در حلقه جانبی.
۳. جایگزینی دقیق خروجی به‌جای regex حریص، با محدود کردن وضعیت جایگزینی به نوشته جاری و پاک کردن آن پس از مصرف.
۴. جلوگیری از افزودن مجدد قطعه‌کدی که شناسه خروجی آن از قبل در محتوا دیده می‌شود.
۵. بررسی فعال بودن و شرایط نمایش هنگام render مستقیم.
۶. گزینه اختیاری «جداسازی کامل HTML/CSS/JS (iframe)» برای هر قطعه‌کد. در این حالت هدر/فوتر/CSS/JS همان قطعه فقط در سند iframe قرار می‌گیرند و در صفحه میزبان چاپ نمی‌شوند، حتی اگر گزینه اجرای سراسری فعال باشد. تغییر ارتفاع فقط از پیام همان پنجره iframe پذیرفته می‌شود.

## محدودیت‌های جداسازی
- پیش‌فرض خاموش است؛ فعال‌سازی خودکار روی کدهای قبلی می‌تواند ابزارها و ارتباطات آن‌ها را بشکند.
- مناسب ویجت، ابزار، ماشین‌حساب و سند مستقل است؛ برای متن اصلی مقاله سئومحور توصیه نمی‌شود. نباید روی نمایش/ایندکس محتوای srcdoc مثل متن معمول نوشته حساب کرد.
- iframe با sandbox و بدون allow-same-origin اجرا می‌شود. JS داخل آن نمی‌تواند DOM قالب و سبد خرید والد را دستکاری کند. دسترسی به storage/cookie و برخی APIها یا منابع شبکه ممکن است محدود شود.
- PHP، تاخیر تعاملی و تاخیر viewport افزونه در این حالت اجرا نمی‌شوند. PHP یک قابلیت سمت سرور است و این جداسازی، sandbox برای PHP نیست.
- استایل قالب، jQuery و کتابخانه‌های والد به iframe منتقل نمی‌شوند. منابع خارجی و CSP ممکن است روی کارکرد آن اثر بگذارند.
- لینک‌ها به‌صورت پیش‌فرض در پنجره جدید باز می‌شوند؛ فرم‌ها مجوز ارسال ندارند. افزونه همچنان اجازه بارگذاری منابع خارجی توسط کد مدیر را می‌دهد؛ این حالت فایروال شبکه نیست.
- ارتفاع خودکار نیازمند JavaScript است؛ بدون آن ارتفاع اولیه ۶۰۰ پیکسل است. حالت‌های خاص مانند body با min-height:100vh، position:fixed یا اسکریپت‌هایی که دائماً اندازه را تغییر می‌دهند باید در مرورگر آزمایش شوند.

## راهکار مناسب برای همین مقاله
۱. قبل از تغییر، از دیتابیس و قطعه‌کد خروجی بگیرید و در staging تست کنید.
۲. نسخه ۳.۰.۲ را با جایگزینی فایل افزونه نصب کنید؛ افزونه قبلی را از صفحه افزونه‌ها حذف نکنید. ابزار uninstall می‌تواند داده‌ها را مطابق تنظیمات حذف کند.
۳. در قطعه مقاله «اجرای سراسری CSS/JS» را خاموش و محدوده هدر/فوتر را «هوشمند» کنید. هدر/فوتر غیرضروری این قطعه را خالی کنید؛ تنظیم سراسری سایر قطعه‌های سایت را بی‌دلیل تغییر ندهید.
۴. برای راهکار اصولی، HTML/CSS/JS ذخیره‌شده مقاله را ارسال کنید تا قواعد آن دقیقاً بازنویسی شوند. محتوای HTML باید fragment باشد، نه سند کامل. ریشه‌ای مانند <article class="maneli-dieffenbachia-article"> داشته باشد.
۵. CSS مقاله باید زیر همین ریشه تعریف شود. به‌جای body یا header عمومی، از .maneli-dieffenbachia-article و .maneli-dieffenbachia-article .article-header استفاده شود. متغیرها روی ریشه مقاله باشند نه :root؛ keyframes نام یکتا داشته باشند. تبدیل همه سلکتورها با regex راه مطمئنی نیست.
۶. JS مقاله باید جست‌وجوی عناصر و رویدادها را به ریشه همان مقاله محدود کند؛ تغییر document.body، window.onload و handlerهای عمومی نیازمند بازبینی است.
۷. برای مهار موقت، اگر محدودیت سئو/iframe قابل قبول است، جداسازی را فقط روی همین قطعه فعال کنید؛ این گزینه راهکار پیش‌فرض توصیه‌شده برای مقاله نیست.
۸. کش صفحه، CDN، افزونه بهینه‌سازی و فایل‌های ترکیبی CSS/JS را پاک کنید. سپس دسکتاپ و موبایل، هدر، منو، فوتر، مقاله، محصول، افزودن به سبد، سبد خرید و تسویه‌حساب را بررسی کنید.

هیچ‌کدام از تغییرات محلی روی سایت شما اعمال نشده‌اند. تضمین عدم تداخل تمام کدهای دلخواه در حالت عادی ممکن نیست؛ برای رفع دقیق این مقاله باید خود قطعه‌کد بررسی شود.

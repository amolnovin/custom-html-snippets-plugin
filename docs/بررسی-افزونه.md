# بررسی فایل دانلود‌شده

**فایل:** `custom-html-snippets.zip` (۱۴٬۶۰۸ بایت) — آرشیو ZIP سالم، شامل یک پوشه و یک فایل:
`custom-html-snippets/custom-html-snippets.php` (۱۶۴۲ خط)

**افزونه:** «قطعه کدهای سفارشی (HTML/CSS/JS)» — نسخه ۲.۳ — نویسنده: AMOLNOVIN.IR
بدون بدافزار/کد مبهم (obfuscated) یا درخواست شبکه‌ی مخفی. کد تمیز و خوانا با کامنت‌های فارسی است.

---

## ۱) این افزونه چه می‌کند؟

| بخش | توضیح |
|---|---|
| Custom Post Type | `custom_snippet` («قطعه کدهای من») با `public => false` و فقط پشتیبانی از عنوان |
| متاباکس اصلی | شش ادیتور CodeMirror: **PHP، Header، HTML، CSS، JS، Footer** |
| شورت‌کد | `[my_snippet id="123"]` و پارامتر اختیاری `replace="true"` |
| فعال/غیرفعال | سوییچ در سایدبار + دکمه‌ی «تغییر سریع» با nonce از طریق `admin-post.php` |
| اجرای با تاخیر | خروجی داخل `<template class="chs-delay-run">` و اجرا پس از اولین تعامل کاربر (mousemove/scroll/click/keydown) یا حداکثر ۶ ثانیه |
| محدوده هدر/فوتر | «سراسری» یا «هوشمند» (فقط صفحه‌ای که شورت‌کد در آن است) |
| قوانین صفحات | لیست استثنا (exclude) و لیست اجرای خودکار (include) با جستجوی AJAX |
| جایگزینی محتوا | جایگزینی کامل `the_content`؛ در صفحه محصول ووکامرس، مخفی‌سازی گالری/عنوان/قیمت/تب‌ها با CSS + `remove_action` |
| کش | دو ترنزینت یک‌ساعته (`chs_active_snippets_ids`, `chs_shortcode_candidates`) + `wp_cache` برای «محل‌های استفاده» |

## ۲) نقاط قوت

- **nonce و مجوزها در جای درست:** `wp_nonce_field` + `wp_verify_nonce` + `current_user_can('edit_post')` در ذخیره، و `check_admin_referer` در toggle.
- کوئری مستقیم دیتابیس با `$wpdb->prepare` و `esc_sql` نوشته شده.
- اجرای PHP پشت دو گارد: ثابت `CHS_DISABLE_PHP` و قابلیت `unfiltered_html`.
- خروجی‌های مدیریتی به‌درستی با `esc_html/esc_attr/esc_url/esc_textarea` امن شده‌اند.
- کش‌ها در ذخیره/حذف/تغییر وضعیت به‌درستی پاک می‌شوند (`chs_flush_cache`).

## ۳) ایرادها و ریسک‌ها (به ترتیب اهمیت)

### 🔴 بحرانی
1. **`eval($php)` در خط ۱۴۰۸.** اجرای کد دلخواه در فرانت‌اند. گرچه با `unfiltered_html` محدود شده، ولی این بررسی **در زمان نمایش** انجام می‌شود نه زمان ذخیره: اگر کاربر ادمین کدی ذخیره کند و بعداً دسترسی‌اش گرفته شود یا سایت مالتی‌سایت باشد، رفتار غیرقابل‌پیش‌بینی می‌شود. همچنین `eval` با `Throwable` گرفته می‌شود ولی **خطای پارس (ParseError) در PHP 7+ گرفته می‌شود اما فقط اگر کد در همان eval باشد** — یک `exit;` یا حلقه بی‌نهایت کل صفحه را از کار می‌اندازد.
   - پیشنهاد: پیش‌فرض `CHS_DISABLE_PHP` را `true` بگذارید، یا حداقل هنگام **ذخیره** هم `chs_can_edit_php()` را چک کنید (این کار انجام شده) و شناسه‌ی نویسنده را ذخیره و در زمان اجرا اعتبارسنجی کنید.

2. **دو اکشن AJAX بدون nonce و بدون بررسی مجوز:**
   - `wp_ajax_chs_search_posts` (خط ۷۰۷)
   - `wp_ajax_chs_get_page_titles` (خط ۷۴۳)

   هر دو فقط `wp_ajax_` هستند (یعنی نیاز به لاگین دارند) اما **هیچ `check_ajax_referer` و هیچ `current_user_can` ندارند**. یعنی هر کاربر لاگین‌شده — حتی سطح «مشترک» — می‌تواند عناوین نوشته‌ها را جستجو کند و عنوان هر پستی (از جمله **پیش‌نویس‌ها و پست‌های خصوصی**، چون `get_the_title()` بررسی دسترسی نمی‌کند) را استخراج کند. این یک نشت اطلاعات + آسیب‌پذیری CSRF است.
   - اصلاح پیشنهادی در ابتدای هر دو تابع:
     ```php
     check_ajax_referer( 'chs_ajax', 'nonce' );
     if ( ! current_user_can( 'edit_posts' ) ) wp_send_json_error();
     ```
     و در جاوااسکریپت هم `nonce` را با `wp_localize_script` ارسال کنید.

### 🟠 مهم
3. **`_chs_header` / `_chs_footer` / `_chs_html` بدون هیچ فیلتری echo می‌شوند** (خطوط ۱۲۴۵، ۱۲۸۰، ۱۴۲۰). این ذاتاً هدف افزونه است، اما اگر نقشی مثل Editor بتواند این CPT را ویرایش کند، عملاً **XSS ذخیره‌شده‌ی سراسری** دارید. بهتر است capability اختصاصی برای CPT تعریف شود (`'capability_type' => 'chs_snippet'`) یا حداقل ذخیره‌ی HTML/JS نیز به `unfiltered_html` مشروط شود.

4. **`$_POST['chs_scope']` بدون `wp_unslash`** (خط ۹۷۷) — ناسازگاری کوچک با بقیه‌ی کد؛ بهتر است در برابر مقادیر مجاز whitelist شود:
   ```php
   $scope = in_array( $_POST['chs_scope'], array('global','page'), true ) ? $_POST['chs_scope'] : 'global';
   ```

5. **`chs_get_active_snippets_ids()` با `posts_per_page => -1`** — با تعداد زیاد قطعه‌کد و پرایم‌نشدن متا، در هر لود صفحه چندین کوئری متا اجرا می‌شود. ترنزینت کمک می‌کند، ولی بهتر است به‌جای حلقه، از `meta_query` استفاده کنید و `update_post_meta_cache` را فعال بگذارید.

6. **کوئری `LIKE '%[my_snippet%'` روی ۵۰۰ ردیف با `post_content`** (خط ۱۱۰۳) — روی سایت‌های بزرگ سنگین است چون کل محتوای ۵۰۰ پست را در ترنزینت (یعنی جدول options) ذخیره می‌کند. می‌تواند رکورد option چند مگابایتی بسازد. بهتر است `post_content` را در SELECT نگه ندارید و تطبیق را در همان SQL انجام دهید.

### 🟡 جزئی
7. `chs_hide_woocommerce_product_elements()` روی هوک `wp_head` صدا زده می‌شود در حالی که از `the_content` فراخوانی شده — در آن نقطه `wp_head` **قبلاً اجرا شده**، پس `remove_action`ها و بلوک `<style>` عملاً بی‌اثرند. باید به `wp_footer` یا `template_redirect` منتقل شود.
8. `add_filter('the_content', ...)` داخل خود اجرای `the_content` (خط ۱۳۶۴) — اضافه‌کردن فیلتر حین اجرای همان فیلتر رفتار مبهمی دارد و در همان درخواست اعمال نمی‌شود.
9. `chs_current_page_is_excluded` از `in_array(..., true)` استفاده می‌کند و آی‌دی‌ها `intval` شده‌اند — درست است، ولی `get_queried_object_id()` هم int برمی‌گرداند، پس اوکی. صرفاً حواستان باشد اگر جایی مقدار رشته‌ای ذخیره شد، مقایسه بی‌صدا شکست می‌خورد.
10. متن‌ها هاردکد فارسی هستند؛ بدون `__()` و text-domain، ترجمه‌پذیر نیست.
11. `register_deactivation_hook` تابع `chs_deactivate` را ثبت می‌کند ولی هیچ `uninstall.php` وجود ندارد — با حذف افزونه، متاها و ترنزینت‌ها در دیتابیس باقی می‌مانند.
12. فایل با کاراکترهای BOM/تگ بسته ندارد (خط ۱۶۴۲ آخرین `}` است) — این درست است، ولی خط پایانی ناقص به نظر می‌رسد؛ چک کنید کپی کامل باشد.

## ۴) جمع‌بندی

افزونه از نظر معماری خوب و کاربردی نوشته شده و برخلاف خیلی از افزونه‌های مشابه، nonce و escape را رعایت کرده است. **اما دو مورد را قبل از استفاده روی سایت واقعی حتماً اصلاح کنید:**

1. افزودن `check_ajax_referer` + `current_user_can` به دو تابع AJAX
2. غیرفعال‌کردن پیش‌فرض PHP (`define('CHS_DISABLE_PHP', true);` در `wp-config.php`) مگر اینکه واقعاً به آن نیاز دارید

با این دو اصلاح، ریسک قابل قبول است. برای سایت‌های چندکاربره، تعریف capability اختصاصی برای CPT را هم اضافه کنید.
